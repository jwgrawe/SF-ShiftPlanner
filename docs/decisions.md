Reading is forgiving: `;` or `,`, UTF-8 or Windows-1252, an Excel «sep=;» line. One helper (`app/csvfile.py`) does both. Opening a seed file in Excel to *look* is fine; saving it from Excel is not recommended (Excel may rewrite values), and on the hospital PC an edited tracked file would also block `git pull`. |
| D113 | R12 | **Storage: the database is the truth, the seed files are factory defaults.** Best practice for an app like this is both, with clear roles: versioned defaults in the repository (reviewable, the template for a new department) and the live values in the database, changed only through the app and logged. Shift codes and planning rules already work this way (D103/D108); functions, zones, demand, intensity and competency types are still reloaded from the seed on every start and move to the same model as they get in-app editors (generic.md step 2). An export/import of the whole configuration (Excel-friendly CSV or one workbook) gives backup and copying to another department. Personal data never goes in the seed files — the repository is public. |
| D114 | R13 | **«Avvik og tiltak» is built** (Planregler): one registry (`app/contingency.py`) of the judgement calls, each with choices and the owner's Q48 defaults; the code asks it instead of hard-coding. Planning: P1 too few to rotate (cover first / rotate anyway), P2 cap vs. coverage (go over + warn / leave short), P3 target vs. structure (+ P3N notice when the target gives way), P4 «Rullerer ikke» level, P5 nowhere to place (Ad hoc / a zone / unplaced), P6 weekends (demand only / full), P8 roster changed after planning (warn / remake unpublished drafts). Source data: S1 new titles (hold / plan meanwhile), S2 not in the ukeplan (**ukeplan is the truth**: not working that week, merknad — alert if the ukeplan looks incomplete; or use the turnus), S4/S6 thresholds, S5 unplannable shifts **flagged whenever found** (red within N days, yellow later), S7 level. Notices N1–N3 levels. Safety rules stay fixed and are listed. «På vakt uten plassering» now also catches part of a shift. |
| D115 | R13 | **«Ad hoc» is a placement**: a built-in zone and function (staffing mode `adhoc`) open to everyone on duty, no competency needed — for when people distribute themselves or check with a manager. Default for someone who fits nowhere (P5); on the board as its own grey section, only when someone is in it. Part of every department's template. |
| D116 | R13 | **No favourite employee numbers**: the planner's last tie-break is a value that changes daily but is reproducible (hash of date and employee), instead of the employee number. |
| D117 | R13 | **Statistics (Q50)**: for admins only; first figures are the serious findings (over the cap, over the target, «Rullerer ikke») and short-staffing hours per function. Per person within the retention period; anonymous weekly totals kept for three years. Built after the board/admin separation (Q52), since it is admin-only. |
| D118 | R14 | **Heavy work is balanced per hour worked** (Q51): the planner compares *belastningstimer ÷ hours worked* over the utjevningsvindu, not the sum, so part-timers carry no more heavy work per hour than full-timers. Until someone has a couple of shifts in the window, their share is pulled towards the group average (as if 16 h at the average), so a newcomer isn't treated as «fresh». The weekly cap stays in whole days. The measure is called **belastningstimer** in the app (extra load beyond ordinary work; ordinary work = 0 — the 0-baseline is kept, see fairness.md). |
| D119 | R14 | **Endringer i vaktlisten** (Datagrunnlag): a manager records what actually happens — another shift code, own times, or not at work — for a person and day (the day the shift starts). It wins over turnus and ukeplan, also over newer files, until removed; the page shows what turnus/ukeplan said. It also settles a held conflict (two rows the same day), whose source alert then becomes a notice. Placement swaps (who stood where) are edited in the day plan, also afterwards. Kept for the retention period; logged. Real mode only (the demo roster is fixed). |
| D120 | R14 | **The board window**: `python run.py --tavle` opens the board in kiosk mode (Edge, else Chrome; own browser profile in `data/tavle-profil/`; second screen at `--tavle-x`). A browser that opened `/tavle` is only ever shown the board — any other page sends it back (`/tavle/av` undoes it in a browser that got it by mistake). A test fails if the board template or model gains anything beyond names, placements, times and Diverse info. Admin login comes next (Q53). |
| D121 | R15 | **Login through the Windows login** (Q53: everyone is always logged into Windows with the ID card; readers everywhere). The board stays public; everything else needs an administrator once one exists (open with a banner until then). The browser proves the Windows user by Windows single sign-on (Negotiate/SSPI via ctypes, nothing to install); fallback method: the Windows user running the app. One account per manager (Windows accounts); added/removed only in **root mode** — `python run.py --rotadmin` opens the browser with a one-time key that makes that browser root for the run. Sessions in memory (logout, 60 min idle, restart). The log records who did each thing. `python run.py --test-innlogging` checks Windows sign-on on the PC. Supersedes the card-level plan (smart-card-login.md, kept as fallback). |
